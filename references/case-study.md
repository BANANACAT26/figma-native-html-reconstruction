# 方法来源：多画板真实重建案例

## 范围

本 Skill 提炼自一次 Figma 文件固定画板重建：目标页面有多个顶层对象，其中绝大多数是真正画板（其余是画布箭头等非画板节点），各画板尺寸在同一项目内通常统一。最终路线是 Figwright MCP live 节点树 + 原生独立非文字素材 + 真实 DOM 文本 + 固定坐标 + 几何/像素/文本闭环。

## 最终采用的生产管线

1. `frame-manifest.json` 固定画板和节点映射。
2. 读取 live 树，导出最大 TEXT-free 子树，文字另建 manifest。
3. 记录 designBox、renderAABB、pngPlacement、exportSize、effectiveClipRect 和 zIndexChain。
4. 固定 stage 重建 HTML，保留 data-n。
5. 浏览器在与 reference 相同的物理尺寸、DPR=1 下截图，与静态 reference 逐像素比较。
6. 以任一 RGB 通道差超过合同阈值为 mismatch，同时保存 raw、outside、text-region、SSIM、热图和哈希。
7. 增加真实 DOM 文本行盒审计、live↔DOM 绝对/相对几何审计和总览实际可见性复核。

## 几何审计的真实教训

合并审计会产出大量记录，初始重点偏差中常有大量口径问题。后续闭合记录将部分问题分类为：真实几何修复、文本指标重分类、裁剪/坐标空间伪偏差、live/reference 冲突和未解决项。结论是：审计数量不是缺陷数量，必须独立复核测量口径。

尤其是：

- GROUP 子节点重复加父位移造成假大偏差。
- 旋转祖先下的布局盒与 AABB 混比造成假阳性。
- 容器扁平化、位图阴影、文本表格盒和手机屏局部坐标需要专门口径。

## 返修路线

采用“MCP 定位几何问题 → 修改 HTML → 同基准像素复验 → 实际看图”。部分只改善旧 reference 的实验扩大了 live 偏差，被回退。部分 live 与旧 reference 冲突被单列，而非写成普通闭合。

文本问题通过重复 DOM、可见性、分段、行高和真实行盒联合排查。针对性修复覆盖长段落折行、角色换行、表格下方文本和主题块溢出；设计内 nowrap/遮挡不误删。

## 连线返修的真实教训

- 某类含大量旋转位图路径的页面：不同旋转 PNG 内部可视路径偏移不同，需逐条处理；项目主色和辅色路径都是真实内容，不能因看似混乱删除。
- 端点补普通直线被用户否决，最终改为完整连接器，让真正箭头头部接目标，纵向连接器也纳入。
- 另一类页面：新 SVG 漏同步和 SVG 落在 stage 外，先后导致总览无箭头；最终按主干若干条、分支若干条验真实 fit 画面。
- 又一类页面：按用户截图改成中性色正交共享树，保留右侧若干项和节点标记，旧线不再双显。

## 数值目标的边界

最近一次全量按较严口径跑下来，只有少数画板达到 outside-text mismatch ≤1%；其余页面不能写成已达 1%。主要限制包括精确字体、烘焙位图内容/色彩/抗锯齿及 live/reference 版本冲突。

对旧 PNG 做亚像素相位、色彩、缩放、移动扫参以及 OFL 候选字体 A/B 试验，多次造成指标或 live 几何回退，均已回退。文字始终保持 DOM，没有用文字图片化规避。

因此，本 Skill 承诺的是：更快建立正确路线、减少已知返工、保留完整证据、及时回退错误候选；不承诺任意设计稿必然达到某个像素百分比。
